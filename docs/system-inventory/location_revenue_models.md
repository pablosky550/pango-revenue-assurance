# Location Revenue Models

## Purpose

This document identifies and classifies the revenue models observed across customer locations.

The objective is to understand how revenue is calculated, distributed, and settled for each location in order to support Revenue Assurance validation.

Different locations operate under different contractual and financial models. Understanding these models is critical for validating revenue calculations, settlements, owner payments, and Pango revenue recognition.

---

## Revenue Models Observed

| Model                 | Description                                           | Observed Components                    | RA Risk |
| --------------------- | ----------------------------------------------------- | -------------------------------------- | ------- |
| Fixed Transaction Fee | Percentage fee applied to parking revenue             | Parking Revenue, Transaction Fee       | Medium  |
| Revenue Share 70/30   | 70% Owner Revenue, 30% Pango Revenue                  | Owner Revenue, Pango Revenue           | High    |
| Revenue Share 75/25   | 75% Owner Revenue, 25% Pango Revenue                  | Owner Revenue, Pango Revenue           | High    |
| Per Session Fee       | Fixed fee charged per parking session                 | Session Count, Fee per Session         | High    |
| Enforcement Model     | Parking operations combined with enforcement services | Enforcement Fees, Enforcement Activity | High    |
| Call Center Model     | Customer support charges applied to location revenue  | Call Center Fees                       | Medium  |
| Permit Model          | Permit sales and permit-related fees                  | Permit Revenue, Permit Fees            | High    |
| Dispute Model         | Revenue adjusted by payment disputes and dispute fees | Disputes, Dispute Fees                 | High    |

## Revenue Components Identified

| Component           | Description                                  |
| ------------------- | -------------------------------------------- |
| Parking Revenue     | Gross parking receipts generated by users    |
| Parking Refunds     | Refunded parking transactions                |
| Transaction Fee     | Pango processing fee                         |
| Permit Revenue      | Revenue generated from permit sales          |
| Permit Fees         | Fees applied to permit transactions          |
| Enforcement Revenue | Revenue related to enforcement activities    |
| Enforcement Fees    | Charges associated with enforcement services |
| Call Center Fees    | Customer support related charges             |
| Disputes            | Chargebacks and disputed transactions        |
| Dispute Fees        | Fees associated with disputes                |
| Owner Revenue       | Revenue allocated to location owner          |
| Pango Revenue       | Revenue retained by Pango                    |
| Net Receipts        | Final settlement amount                      |

## Example Revenue Structures

| Example Structure                                             | Description                    |
| ------------------------------------------------------------- | ------------------------------ |
| Parking Revenue → Transaction Fee → Net Settlement            | Standard transaction fee model |
| Parking Revenue → 70/30 Split → Owner Revenue + Pango Revenue | Revenue sharing model          |
| Parking Revenue → 75/25 Split → Owner Revenue + Pango Revenue | Revenue sharing model          |
| Sessions → Fee per Session → Settlement                       | Session-based pricing model    |
| Parking Revenue → Enforcement Fees → Net Settlement           | Enforcement-supported model    |

## Revenue Assurance Risks

| Risk Area                   | Description                                     |
| --------------------------- | ----------------------------------------------- |
| Revenue Share Calculation   | Incorrect allocation between owner and Pango    |
| Transaction Fee Calculation | Incorrect fee percentage applied                |
| Session Count Accuracy      | Sessions not matching reported revenue          |
| Refund Processing           | Missing or incorrect refunds                    |
| Dispute Handling            | Disputes not reflected correctly in settlements |
| Enforcement Charges         | Incorrect enforcement fee calculations          |
| Permit Revenue Recognition  | Permit sales not properly recorded              |
| Settlement Calculation      | Incorrect final net settlement amount           |

## Key Observation

The January 2025 location statements demonstrate that Pango operates multiple revenue models across its customer base.

Revenue Assurance cannot rely on a single reconciliation methodology.

Validation rules will likely need to be applied by:

* Customer
* Location
* Contract Type
* Revenue Model

Understanding and classifying these revenue models will be a foundational requirement for the future Revenue Assurance engine.
